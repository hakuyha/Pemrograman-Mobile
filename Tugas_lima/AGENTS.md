# Project & Anti-Slop Guidelines

## Anti-Slop Principles
- **Direct & Concise Communication**: Be straight to the point. No fluff, generic preambles, apologies, or conversational filler.
- **High-Quality Code**:
  - Full implementations only: no dummy placeholders (`// TODO: implement later`) or half-baked logic.
  - No redundant/obvious comments that just describe what the code syntax does.
  - Avoid unnecessary boilerplate, over-engineering, and speculative abstractions.
  - Follow idiomatic Flutter / Dart and backend conventions existing in the project.
- **Verification**: Ensure code compiles cleanly and passes static analysis (`dart analyze` / linter).
